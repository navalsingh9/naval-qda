Architecture at a glance

Frontend
React 18 + Vite
Zustand (state)
No manual DOM manipulation

Real Node modules in the
main process — not a webpage script

app.getPath('userData')

electron-builder →
nsis (.exe) · dmg · deb/AppImage
AI Assist
Optional, pluggable (backend/ai.js)
Gemini by default — bring-your-own free key
Why IPC instead of a local HTTP server — the backend runs as plain Node modules inside Electron's main process (full fs/native-module access, no sandboxing headaches for ffmpeg/whisper). The renderer never touches Node directly: preload.js exposes a narrow, typed API via contextBridge, and React components call it like any async function (await window.api.applyCoding(...)). This is the same "real backend, dumb frontend" separation as the original FastAPI plan — just both sides are JS, and shipped as one binary instead of a server + browser tab. If you'd rather keep a genuine HTTP server (e.g. to reuse it for a future web version), swap S1 to spin up Express in the main process and have the renderer hit localhost instead of IPC — everything from S2 onward stays the same.

What to build

          
    
            
  • FMigration: settings key-value table (encrypted API key blob, provider id, model name, enabled flag) and ai_suggestions table (node_id/source_id, kind, payload_json, status), plus an ai_generated boolean on memos — run through the Session 2 migration runner, don't hand-edit schema.sql on an app that's already shipped
    • 
            
  • Mbackend/providers/gemini.js — wraps the @google/genai package using the stable generateContent call, not the newer Interactions API (Google's own docs mark Interactions as Beta and recommend generateContent for production as of mid-2026); structured JSON via responseSchema when a schema is passed, a typed rate-limit error on HTTP 429; default model is a single exported constant, not buried in logic — this model lineup has already moved more than once this year
    • 
            
  • Fbackend/ai.js — a tiny provider registry ({gemini: require('./providers/gemini')}) so a second backend later is a new file plus one line, not a rewrite; getApiKey/setApiKey via Electron's safeStorage.encryptString/decryptString — never plaintext in SQLite, never logged, never in a thrown error's message
    • 
            
  • LsummarizeSource(sourceId) and suggestChildCodes(nodeId) — the latter enforced with a JSON schema (name, rationale, evidence spans); validate every returned offset against that source's real content length and clamp or drop anything out of range before it's ever stored — the model can hallucinate positions
    • 
            
  • SresolveSuggestion(id, action) — accept creates the real node + coding rows exactly as manual coding would (reuse coding.createNode/applyCoding); reject only marks the row, touches nothing else
    • 
            
  • MRate-limit handling — single-flight queue (max 1 concurrent Gemini call), exponential backoff with jitter on 429, surfaced as a typed rate_limited error through Session 10's wrap() shape rather than a raw throw; free-tier limits are genuinely tight on some models and a burst of clicks will hit them
    • 
            
  • FIPC + preload wiring in Session 10's namespaced pattern: ai:summarizeSource, ai:suggestChildCodes, ai:listSuggestions, ai:resolveSuggestion, ai:testApiKey, settings:setAiApiKey, settings:getAiConfig — the last two never send the decrypted key back to the renderer
